Capability-sandboxed bytecode language with a self-hosting C VM.

Run untrusted or AI-generated scripts in-process with deny-by-default network and filesystem capabilities, hard instruction and memory caps, and a self-hosted compiler embedded directly inside the standalone CLI.

Technical Benchmark Report (Head-to-Head)

Measured on Linux x86_64 via python3 benchmarks/head_to_head.py using a minimal C wait4() + CLOCK_MONOTONIC harness (median of 5 runs). Workload: recursive Hanoi(18) (262,143 calls) + 50,000 skyline block placements, asserting identical output 262143 1666691668.

Runtime Cold-Start Hanoi18 + 50k Primes (25k) Policy Scrub (5k) Peak RAM
Vidyax AOT Native 2.35 ms 41.24 ms 72.88 ms 16.04 ms 3.80 MB
Vidyax C VM (vxvm .vxc) 2.87 ms 177.30 ms 97.20 ms 22.98 ms 3.64 MB
Vidyax Standalone CLI (.vx) 5.89 ms 196.29 ms 113.25 ms 22.93 ms 3.61 MB
Lua 3.24 ms 28.08 ms 13.30 ms 21.63 ms 2.59 MB
Rust (rustc -O) 2.86 ms 4.67 ms 4.52 ms 4.61 ms 2.23 MB
Python 3 (CPython) 46.20 ms 82.08 ms 67.78 ms 39.25 ms 10.71 MB
Node.js (V8 JIT) 59.68 ms 70.83 ms 71.07 ms 66.53 ms 72.91 MB
C (gcc -O2) 2.18 ms 2.68 ms 4.19 ms 2.21 ms 1.69 MB

Honest trade-offs: C and Rust remain much faster in raw compute because they use unboxed machine integers with no GC safepoint checks; Lua's register VM outperforms Vidyax's current stack-based VM. Vidyax trades raw loop throughput for dynamic tagged values, built-in capability sandboxing, and ~2.5 ms cold-start without containers.

Language & Sandbox Examples

Lexical Capability Sandbox

Permissions can only be reduced, never escalated, and are inherited by tasks spawned via go.

sandbox deny net, fs:
    clean: trim(lower("REPORT.TXT"))
    print clean
    # writefile(...) raises a catchable error here

Concurrent I/O & Verification

Run network/AI calls concurrently with data-race-free GIL scheduling and verify self-hosting via ./bootstrap.sh.

use ai

a: go ai.ask("Explain gravity in one sentence")
b: go ai.ask("Explain osmosis in one sentence")
print wait(a)
print wait(b)
